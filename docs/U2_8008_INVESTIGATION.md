# 初代 U2 / 8008：缓存电压与刷新调查

核对日期：2026-10-27。来源：[Issue #1](https://github.com/SHISGAY114514/pulse-wireless-battery/issues/1)。问题仍未解决；本页不宣称持续无线电量刷新已通过。

## 已有观察与证据边界

报告者的设备为初代 U2 `04A5:8007 / 2027`、原装小接收器 `04A5:8008 / 8027`。以下为社区报告，本项目没有该组合的本机实测或 2027 / 8027 镜像：

| 请求（16 字节，补零） | 回复（16 字节，补零） | 可以确认的解释 |
|---|---|---|
| `08 B4 40` | `09 80 27 01 C8` | 报告的 8027 版本帧；偏移 3 为 `01`，含义未知 |
| `08 B4 15` | `09 01 8D 00 C8` | 大端原始值 397；沿用已知电压单位解释为 3.97 V，旧固件内部换算链未核验 |

基线后 27 次约每五分钟查询均为 397。独立重开句柄的探针也读到 397；这降低了单个进程或句柄缓存问题的可能性，但无法定位 ADC、RF 上报或接收器缓存是否停滞。期间约 48 分钟有输入、最后约 37 分钟无输入，不能当作全程持续运动。输入链路活动不等于电池遥测更新。

相同量化值既可能来自新采样，也可能来自旧缓存。数值发生变化也只能证明返回值不同，不能精确反推出采样时刻或周期。Windows BatteryLife 为空不否定私有查询。开关、充电、模式切换后的变化不能作为不重连连续无线刷新的证据。

## 本次新增的 2511 离线证据

镜像 SHA-256：`340475345c20b6eabadc67fd71ba9df91a08f4afb004aaad42ce7e1cc55514ff`。来自已记录的官方 ER2-80 v1.0.13.0 工具中的 `Mouse_Tx_U2.bin`。以下使用 Flash 基址 `0x1000` 的运行地址，**不是文件偏移**。

- 服务函数 `0xDC38` 先调用 `0x9D7C`；返回 4 时提前返回。RAM `0x200000EC + 3` 为零时也提前返回。这些字段的完整状态语义尚未确定。
- `+0x56` 状态为 3 或 5 时，`0xDC64–0xDC6C` 增加 `+0x14` 的 16 位计数并比较 500。
- 恰好达到 500 时，`0xDCAA–0xDCAC` 将 `+9` 标志置 1，并清零计数。
- 静态反汇编中，组包路径 `0x5D86–0x5D8C` 检查同一标志并选择 `0x20` 类型，前面还存在更优先的 `0x60` 分支。`0x5E40` 调用已验证的电压编码函数 `0x3580`。本次模拟只执行服务计数函数，没有模拟完整组包和 RF 链路。

[复核脚本](../tools/verify_zowie_u2_service.py) 对 mode getter 返回 0 / 4、使能 0 / 1、状态 0–7、计数 0 / 498 / 499 / 500 / 65535 共 **160 组**合成输入执行真实指令，无差异。结果见 [u2-service-evidence.json](u2-service-evidence.json)。

```powershell
python -m pip install -r requirements-research.txt
python tools/verify_zowie_u2_service.py path/to/Mouse_Tx_U2.bin
```

这个结果**不能**证明服务按固定时间调用、ADC 刚采样、待发送包已送达，或原装 8008 接收器得到更新；更不能外推到旧鼠标 2027 / 接收器 8027。项目已有的 8507 镜像哈希和查询分派验证，也不等于对“2511 + 升级后原装小接收器”持续放电的实测。

## 程序处理与可选诊断

自动面板仍仅识别 8008，不发送查询、不套用 2511 的档位阈值。DW 解析器仍严格要求其已验证的回复格式。新增独立源码工具 [zowie_u2_diagnostic.py](../zowie_u2_diagnostic.py)，专门处理本 issue 报告的 `8027 / 01` 版本帧，不改变日常显示。

在 Windows、Python 3.10+ 的仓库根目录运行（不是 v1.0.0 EXE 的命令选项）：

```powershell
# 默认仅查询一次；日志必须是新文件。
python zowie_u2_diagnostic.py --output u2-cache-once.jsonl

# 可选：一次基线及后续 27 次查询，间隔五分钟。
python zowie_u2_diagnostic.py --samples 28 --interval 300 --output u2-cache-session.jsonl
```

- 只选择一个 `04A5:8008` 物理设备的一组 `FF03 / FF04`、16 字节接口；多个接收器或接口不明确时，在打开 HID 前停止。
- 每次以 `B440 → B415` 顺序查询。版本回复不精确匹配已报告帧时不发送 B415。未加入 B425、未知命令扫描、配置修改、重启、配对或升级。旧版命令依据是 issue 的实际回复，并非已取得旧固件做了静态验证。
- 复用现有卓威互斥锁；它只能协调使用同一锁的程序。采集时不要并行运行其他私有 HID 探针或更新器，以免无命令回显的回复被交叉消费。
- 每行立即写入 JSONL，保存原始回复、主机查询及接收时间、原始整数和电压解释。`sampled_at` 和 `mouse_firmware` 为 `null`，`freshness` 始终为 `unknown`；不输出百分比或档位。
- `value_changed` 只比较相邻成功查询值，不作为“新 ADC 样本”判据。`timing_gap` 标记明显超出请求间隔的查询间断，不在恢复后突发补查询。
- 每次重新枚举并比较物理身份与接口；发现缺失、更换、读取失败即结束会话。查询间隔内的短暂重连可能无法发现，故日志不能证明全程无重连；也不记录输入活动或充电操作。
- 不记录原始设备路径、序列号或 ContainerId；接收器标识为哈希。不会覆盖已有日志，Ctrl+C 保留已写记录。最多 289 次、计划跨度不超过 24 小时。

工具的用途是统一证据格式，**不是修复连续刷新或证明实时电量**。现有记录已经有效，不要求报告者为了使用该工具重复原实验。

## 对下一步研究的约束

当前没有已确认可强制旧 U2 新采样或重新上报的只读命令。在已分析的较新接收器镜像中，B425 仅读鼠标版本缓存；非零或前后相等不是电压新鲜性证据。8027 上该命令还未验证，不为探测新鲜性而新增发送。

后续应优先取得来源及哈希可核对的 2027 / 8027 镜像，追踪 ADC 写入、待发送条件、RF 包与接收器缓存写入；或审查已有的脱敏日志和匹配硬件的连续无线数据。不能仅凭相同版本号、升级路线、离线查询通过就宣称刷新已修复，也不以升级作为当前解决方案。
