# 本次重构后的设备范围

新增路径覆盖 ASUS 鼠标 29 个 USB 身份、VGN MouseEnc 33 个、VGN / ATK Weisheng 4 个、AULA / AJAZZ 接收器 6 个。身份数包括有线与无线版本，**不是 72 款实测设备**。精确白名单见 `receiver_protocols.py`、`aula_proto.py`；需要集合、报告 ID、长度和有效回复同时满足条件。ASUS Omni 共享鼠标通道暂不在新增鼠标路径内。

DARKRIM 的原有读取现已接入常驻面板，增加 CRC、查询通道和完整 TLV 校验。标准 HID、旧厂商和独立协议的边界见下方原有说明。

标准 HID 统一支持描述符范围和正确的报告 ID；一个字段失败不会阻断其他字段。无 ContainerId 时先用 USB 物理父节点分组，无法确定身份时保留独立接口，避免把同型号的两个接收器混在一起。

当前不能承诺读取市场上“绝大多数”2.4G 外设：厂商私有协议、固件差异以及未暴露的电量字段仍需要逐协议适配。RK R98 自动电量入口仍未确认，维持不可用，不显示人工灯格或猜测百分比。本次实测与新增路径验证范围见 [最新验收](VALIDATION.md)。

# 动态发现与电量协议支持

PULSE 现在按物理外设动态发现设备，不再固定显示两台。它是使用 Windows HID API 的用户态电量监控程序，无需安装内核驱动。通用发现并不意味着所有私有协议都能直接读取。

## 物理设备去重、热插拔与托盘

- 优先使用 Windows `DEVPKEY_Device_ContainerId` 合并同一设备的 HID 集合。本机雷蛇鼠标的 10 个集合只计作一台设备；两个相同型号、不同 Container ID 的接收器分别处理。系统无法提供 Container ID 时回退到接口标识及可用序列号，回退分组仍有局限。
- 每次刷新重新枚举设备；注册 HID 设备通知后，插拔事件经防抖触发刷新，即使自动轮询关闭也会响应设备变化。忙时收到插拔事件会在本次读取结束后补扫。
- 拔出设备后移除卡片与托盘图标并清除缓存。迈从休眠旧值最多保留十分钟，以灰色标注上次成功时间及“非当前值”，不继承充电状态；其余失败隐藏此次无效值并保留原因。
- 最多三张卡片同屏，更多设备分页；计数按全部已发现设备计算。托盘图标随设备增删，无设备时保留一个 PULSE 入口。
- 多个卓威接收器各自维护缓冲。可在各自“连接详情 → 设置此接收器的鼠标型号”中保存独立型号；没有独立设置且同时存在多个卓威接收器时，只显示电压，不把全局型号套到所有鼠标上。

当前按 USB 物理连接显示卡片；同一只鼠标同时连接接收器和数据线时，若缺少可信的关联身份，可能显示两个明确标注连接方式的卡片。HID++ 可以展开同一接收器下读到电量的多个逻辑设备，接收器数量仍按物理接收器去重；其他共享协议未必能逐台展开。

## 雷蛇只读协议

协议事实参考 [OpenRazer](https://github.com/openrazer/openrazer) 的 [鼠标驱动](https://github.com/openrazer/openrazer/blob/master/driver/razermouse_driver.c)、[通用报文](https://github.com/openrazer/openrazer/blob/master/driver/razercommon.h) 和 [电量命令](https://github.com/openrazer/openrazer/blob/master/driver/razerchromacommon.c)。PULSE 独立实现，没有复制其 GPL 运行代码。

Windows Feature Report 长 91 字节：首字节是报告 ID 0，随后为 90 字节雷蛇报文。类 `07` 的命令 `80` 查询电量、`84` 查询充电；事务 ID 随型号为 `1F / 3F / FF`。电量位于参数区索引 1，范围 0–255，按比例取整为 0–100%。可更换电池的型号不查询充电状态。

程序检查长度、报告 ID、事务 ID、命令、状态、保留字段和 XOR 校验和。只接受成功状态；忙、无响应、协议错误等不显示为 0% 或上次电量。电量成功而充电查询失败时，保留此次有效电量，将充电状态标记为未知。

系统独占鼠标集合时，使用 Windows 允许的零访问权限句柄发送这两个已确认的 Feature 查询，不抢占输入设备，不修改 DPI、灯效、固件或配对。CRC 覆盖 90 字节报文的索引 2–87。电量命令构造器拒绝其他命令。

## 标准 HID 的边界

接受 General Device Controls `06:20`、Digitizers `0D:3B` 电池强度，以及 Battery System `85:64 / 85:65` 充电比例字段；按逻辑最小 / 最大值换算，超出声明范围则拒绝。

`06:29` 是无线信号强度，`85:66` 是剩余容量，不能作为电量百分比。未知设备不会套用通用锂电池电压曲线。自动厂商适配仅使用内置协议，不执行旧调试工具保存的自定义请求。

## 本次验证

测试覆盖物理设备去重、同型号多接收器、热插拔、未知协议不写入、标准 Feature / Input / Usage Range、迈从空身份与缓存过期、键盘字段、HID++ 回复匹配/多槽计数/Windows 报告长度，以及真实 Tk Canvas 上的原生粗档、缓存灰色、三卡片和分页。

雷蛇在本次初始连接时已完成实机电量 / 充电读取。随后用户暂时无法重新连接，因此三台设备同时在线的最终打包验收使用协议和布局测试覆盖，未冒充新的三设备实时测量；当前卓威与漫步者仍可做实机回归。
